## 결론 먼저 — 라우팅 초안

전 항목이 **판정 등가성 게이트 통과를 전제**로 한다. 게이트를 못 넘으면 그 역할은 제미나이(또는 상위 티어)에 남는다.

| 호출 | 기본 백엔드 | 근거 |
|---|---|---|
| 채연·은상 Agent | 제미나이 Flash (키풀) | 매 루프 기억 소거 → 축적 데이터 없음 · 호출 최다 · 지연 민감 |
| **민석 Agent** | **로컬 14B** | 유일한 메모리 유지 NPC = 플레이어 데이터 최다 축적 → 최민감. 단 [민석의 긴장](#민석의-긴장) 참조 |
| Planner | 제미나이 | 루프당 1회 · 민감도 낮음 |
| Evaluator | **PM 결정** | 데이터 최다(프라이버시) vs 컨텍스트 최장(역량)의 충돌 지점 |
| Advisor (침묵 권고) | 로컬 8~14B | 수치는 코드가 계산, 문장만 생성 |
| 손상 1층 (대사 미세 변형) | **코드** — LLM 불사용 | im-not-ai `corruption_engine` 방식으로 결정적 구현 |

## 1. 왜 하이브리드인가

전부 외부 API는 가장 쉽고, 그래서 해커톤에서 기술 스토리가 없다. 전부 로컬은 공개 투표 동시성에서 무너진다.
**측정으로 정당화된 하이브리드**는 둘 다 이긴다 — 기획서 9.4의 *"어댑터는 교체 비용을 낮추고, 벤치마크는 교체해도 되는지를 증명한다"* 의 다음 문장이 이것이다:

> 등가성이 증명된 역할만 로컬로 내렸다. 여기 그 숫자가 있다.

## 2. 판정 등가성 프로토콜

같은 *텍스트*는 나올 수 없으므로 비교 대상은 **구조화된 판정**이다. 8.5(계산은 코드, 판단은 LLM) 덕에 LLM 출력이 이미 JSON 판정이라 필드 단위 비교가 된다.

| 축 | 비교 방법 | 예상 |
|---|---|---|
| 의심/신뢰 델타 | 같은 발화 → 방향·크기 허용오차 내 일치율 | 로컬 14B 근접 가능 |
| 도구 호출 판단 | `ask_npc` 호출 여부·대상 일치율 | 근접 가능 |
| 재계획 트리거 | 발동 여부 일치율 | 근접 가능 |
| 대사 자연성 | 문자열 비교 불가 → im-not-ai `metrics.py` 점수 분포 | **여기서 갈릴 것** |
| Evaluator 원인 체인 | LLM-judge 교차 채점 | 로컬 열세 예상 |

**규칙 두 개.**

1. **자기일관성이 상한이다.** 모델은 자기 자신과도 항상 일치하지 않는다(11.1 "같은 발화 반복 투입"이 이걸 잰다). 제미나이가 스스로 87% 일치하는 판정에서 로컬이 85% 교차 일치하면 등가로 판정한다. 게이트: `교차 일치율 ≥ 자기일관성 − ε`, 스키마 통과율 기준치 이상, p95 지연 SLA 이내.
2. **캐릭터별 대본을 가른다.** 민석용 대본(지난 루프 발화에 반응하는 케이스 포함)은 채연·은상용보다 어렵다. 역할×캐릭터 단위로 게이트를 따로 통과시킨다.

예상되는 발견: **판정(구조 필드)은 로컬이 등가에 도달하고, 대사 생성(한국어 뉘앙스)은 못 미친다.** 이 경우 판정/발화 분리 라우팅(호출 2배, 비일관성 위험)이 선택지로 열리지만, 3주 범위에서는 역할 단위 라우팅으로 시작하고 분리안은 측정 결과가 실제로 갈렸을 때만 연다.

## 3. 오케스트레이션 — LLM 포트 뒤에 라우터 한 겹

```
[Agent / Planner / Evaluator / Advisor]
              │
         LLM 포트 (기획서 9.1 — 변경 없음)
              │
       ┌── 라우터 어댑터 ──┐    ← 추가되는 것은 이 한 겹
       │   routing.yaml    │       역할×캐릭터 → 백엔드 매핑은 설정, 코드 아님
       └──┬────────────┬───┘
          │            │
     로컬 (vLLM)   제미나이 (키풀)
```

규칙은 셋뿐이다. 더 만들면 3주를 잡아먹는다.

1. **정적 매핑** — `routing.yaml`에 역할×캐릭터별 기본 백엔드. 게이트 통과 항목만 `local`
2. **에스컬레이션** — 스키마 N회 실패 / AI-티 린트 실패 / 지연 SLA 초과 → 그 호출만 반대편으로 승격. 하네스 재시도 경로(8.6)에 분기 하나
3. **셰도우 모드** — 제미나이가 처리한 호출의 x%를 로컬에도 태워 판정만 로깅(응답 미사용). 대본 등가성 ≠ 실플레이어 등가성이므로, 라이브 등가성 데이터가 계속 쌓여야 주장이 안전하다. 킬스위치는 설정 플립(재배포 없음)

**폴백 사다리** (제미나이 429 대응):

```
호출 → 키#1 → (429) → 키#2 → … → (풀 소진) → 로컬 14B
```

무료 한도 초과를 로컬이 받아내는 구조 — 자원 한계 해결이 그 자체로 시연 장면이 된다.

**인스펙터 연동**: 판정 로그(8.8)에 `backend: local-qwen3-14b | gemini-flash` 필드 하나 추가.
발표에서 인스펙터를 열고 *"이 판정은 로컬이, 이 판정은 API가 했습니다. 구분되십니까?"* — 관찰가능성 스토리와 하이브리드 스토리가 한 화면에서 만난다.

## 4. 백엔드 구성

**로컬 — 서버 자원 VRAM 16GB · RAM 32GB 기준**

| 구성 | VRAM | 판정 |
|---|---|---|
| 14B Q4 (Qwen3-14B, EXAONE급) + 임베딩(~2GB) | ~12GB | **주력.** Agent·Advisor 겸용 |
| 32B Q4 | ~19GB → RAM 오프로드 | 3~8 tok/s. Evaluator(루프당 1회)만 감내 가능 |
| Qwen3-30B-A3B (MoE, 활성 3B) | 부분 오프로드 | 32B급 품질이 필요할 때 이 카드의 상한 |

**제미나이**

- 티어 매핑: Flash-Lite(Advisor 예비) / **Flash(Agent)** / Pro(Planner·Evaluator) — 9.4의 역할별 요구 특성과 1:1
- Evaluator에 특히 유리: 긴 컨텍스트로 루프 로그 전량을 요약 없이 투입 가능
- `responseSchema`는 JSON Schema의 부분집합(OpenAPI 스타일) — 복잡한 union·조건부 스키마 불가.
  **로컬 constrained decoding과 공유하는 "양쪽이 다 소화하는 최소 스키마"를 공통 계약으로** 잡고, API 계약 동결(D-12) 때 함께 확정
- 무료 티어 유의: RPD(일일)는 넉넉해도 **RPM(분당)이 스파이크에 약하다.** 429 폴백 필수. 입력이 모델 개선에 쓰일 수 있음(PM 결정 항목)

## 5. 보안 라우팅 — 민감도 경계는 메모리 정책이 긋는다

민감도 = **그 호출이 들고 있는 플레이어 데이터의 양**. 이건 메모리 정책(8.4)이 이미 캐릭터별로 갈라놨다.

- 채연·은상: 매 루프 소거(5% 잔류) → 축적 없음 → 외부로 보내도 가벼움
- 민석: 유일한 유지 → **플레이어의 루프 전체 행동 프로파일** 축적 → 로컬
- Evaluator: 루프 전체 로그 = 데이터 최다 → PM 결정

> 메모리가 유지되는 유일한 NPC — 그래서 플레이어 데이터를 가장 많이 든 민석만 로컬에서 돌렸다.
> 아키텍처(메모리 비대칭)가 보안 경계까지 그어줬다.

8.4의 "아키텍처가 서사를 지탱한다"에 "보안도 지탱한다"가 얹힌다.

### 민석의 긴장 {#민석의-긴장}

보안상 가장 로컬이어야 할 민석이, 역량상 가장 센 모델이 필요한 캐릭터다 — 거짓말을 즉시 간파해야 하고(5.2), 루프 교차 일관성을 유지해야 하는 안타고니스트. 민석 전용 대본으로 게이트를 따로 돌리고, 로컬 14B가 못 넘으면:

1. 민석만 **유료 제미나이** (학습 미사용 → 프라이버시도 해결)
2. 로컬 **30B-A3B로 승급** (오프로드 감내)

어느 쪽이든 숫자를 보고 정한다.

## 6. im-not-ai(휴머나이즈 KR) 활용 3처

[epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai) — MIT 라이선스, 제출물 포함 가능.

| 자산 | 게임에서의 자리 |
|---|---|
| `ai-tell-taxonomy.md` (82패턴) | **NPC 대사 린트** — Agent 출력에 정규식 검출, 걸리면 하네스 재시도 경로로. 스키마 재시도와 같은 구조라 공짜로 얹힘 |
| `metrics.py` (표준 라이브러리만) | **9.4 벤치마크에 "한국어 자연성" 축 추가** — 로컬/제미나이 후보를 같은 지표로 채점. 뉘앙스를 감이 아니라 숫자로 |
| `corruption_engine.py` | **손상 1층의 코드화** — 의미 보존 보장 미세 변형 역주입 + 자가 검증. 기획서 12.3이 "프롬프트 튜닝 필요, 컷 1순위"로 둔 항목이 LLM 0원 항목이 된다 |

한계: 탐지·교정·측정 도구이지 작은 모델의 *이해력*을 올리진 않는다. 판정 뉘앙스는 여전히 모델 크기 문제. taxonomy는 문어체 기준이라 구어 대사에는 패턴을 걸러 적용.

## 7. 실행 순서 — 절대 방어선(12.3) 뒤에서

라우터는 방어선 ①~⑤가 돌고 난 뒤의 이야기다. 다행히 등가성 *측정*은 무거워도 라우팅 *구현*은 어댑터 한 겹 + 설정 파일이라 가볍다.

| 시점 | 할 일 | 산출물 |
|---|---|---|
| 코어 가동 직후 | 발화 대본 테스트셋 확정 (11.1 실험과 겸용, 민석용 별도) | 재생 가능한 시퀀스 N개 |
| 중반 | 양쪽 백엔드 동일 재생 → 역할×캐릭터×축 등가성 매트릭스 | **라우팅 결정표 + 근거 숫자** |
| 결정 | 게이트 적용 | `routing.yaml` 확정 |
| 공개 투표 | 셰도우 모드 on | 라이브 등가성 로그 |

측정이 밀리면 **"전 역할 제미나이 + 셰도우 로컬"로 제출해도 스토리가 유지된다** — "등가성 데이터를 쌓는 중이며 게이트를 넘는 역할부터 내린다"도 완결된 주장이다.

## 발표 문장 후보

> 가장 쉬운 길은 전부 외부 API였다. 우리는 역할별로 판정 등가성을 측정했고,
> 증명된 역할만 로컬로 내렸으며, 그 라우팅 테이블의 숫자를 지금 보여드린다.

- "로컬 14B가 자연성에서 몇 점 차로 밀리는데 판정은 등가고 비용은 0이다"
- "무료 한도를 넘는 순간, 로컬이 받아낸다" (429 폴백 시연)
- "플레이어 데이터를 가장 많이 든 민석만 로컬에 뒀다 — 메모리 비대칭이 보안 경계다"
- "이 판정은 로컬이, 이 판정은 API가 했다. 인스펙터에서 구분되는가?"
